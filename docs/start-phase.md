### Как дорожки не ждут друг друга

Четыре приёма, из-за которых никто не блокирует остальных:

1. **Контракт уже полный.** Все поля снимка, которые понадобятся B и C (сейсмособытия, опасности, буря, спутник, образцы), существуют с первой минуты — просто пока пустые. A наполняет их поведением; B и C пишут отображение сразу.
2. **Площадка `?dev=<имя>`** (задача C0): любой компонент открывается на подготовленных данных, без сервера и без ожидания A. Подготовленные данные у каждой дорожки в своём файле.

4. **Автосбор вместо общих списков.** Словари текстов и страницы площадки подхватываются по маске файлов (`import.meta.glob`). Добавил свой файл — он уже работает; общий файл-реестр править не нужно, конфликтовать не на чем.

## 3. Правила на всю фазу

1. **Одна задача = одна ветка = один PR.** Ветка `a/<задача>`, `b/<задача>`, `c/<задача>`; живёт до двух часов. Слияние squash, когда CI зелёный.
2. **Перед пушем:** `git pull --rebase origin main && npm run check`.
3. **Чужие файлы не трогать** (таблица в разделе 1).
4. **Горячие файлы** (ARCH 13.2) — только отдельным крошечным PR с объявлением в чате. `main.tsx` и `App.tsx` в этой фазе правит только C.
5. **Каждая задача A приходит с тестами.** Список тестов дан в задаче; ассистенту говорить: «сначала напиши эти тесты, потом реализацию».
6. **Ничего не ставить через npm.** Всё нужное уже установлено.
7. **Не уверен в поведении — смотри `product-logic.md`.** Нет ответа — спроси и допиши туда одну строку.
8. **Застрял дольше 20 минут** — сказать остальным. Пять минут вдвоём дешевле часа в одиночку.

7. Астронавт идёт от корабля: кислород падает; бегом (Shift) — быстрее.

Если отстаёте, резать в таком порядке: B5 (свет v2) → A5 (спасение) → окна спутника в A4 → бейджи и Ready в C3 → окно настроек в C5.

**Не резать:** A1, A2, A3, A6, B1, B3, B4, C1, C2 и шесть индикаторов из C3 — без них нет игры или не выполнено требование кейса.
